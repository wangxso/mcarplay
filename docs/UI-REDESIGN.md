# UI 重构设计方案（草案）

分支：`feat/ui-redesign`（基于 `feat/connection-stage-display`，含分层连接进度条）。状态：**仅设计，尚未改代码**。
本文是讨论稿：第 8 节的问题确认后再定稿、拆 PR。

## 1. 目标与非目标

目标

- 手机端三件事一眼可见：**现在连到哪一步**、**下一步该做什么**、**出了问题怎么导出**。
- 把 2975 行的 `MainActivity` 和 1943 行的 `activity_main.xml` 拆成可单独修改、可单独测试的屏幕和组件。
- 一套设计令牌（颜色、字号、间距、圆角）和一组通用组件，手机端、设置页、车机桌面、对话框共用。
- 手机端设置与车机端设置继续共用同一套面板（现状已是如此），重构后保持。

非目标

- 不改连接、协议、媒体链路的行为；不动 `SessionController` 的状态流转。
- 不新增权限，不改包名、`applicationId` 和各 Activity 的 `exported` 属性（`DockActivity`、`GridActivity`、`BtSnoopActivity`、`SilentProjectionActivity` 是被外部拉起的入口）。
- 不在没有真车证据时声称某车机界面表现已验证（见第 7 节）。

## 2. 现状盘点

| 项 | 现状 |
| --- | --- |
| 技术栈 | 纯 Views + XML，`appcompat`，未引入 Material 组件库或 Compose；卡片、按钮、开关全部用 `shape`/`selector` 自绘 |
| 手机主界面 | `MainActivity.kt` 2975 行、约 83 个函数，同时负责：连接流程与权限引导、目标蓝牙设备扫描/配对、车机检测向导入口、日志控制台、诊断导出、壁纸、语言、更新、残留显示清理 |
| 主界面布局 | `activity_main.xml` 1943 行、78 个带 id 的视图，一个 ScrollView 里堆了：英雄卡 → 连接准备 → 自检/外接车机 → Wi-Fi/音频 → 车机显示 → 高级（折叠）→ 日志（折叠）→ 语言/更新/抓包/声明/调试桥 |
| 样式 | 布局里写死的颜色 113 处（主布局 23 处）；字号 12 种（12sp 52 处、13sp 28 处、14.5sp 22 处、11.5sp 21 处……），没有字号阶梯 |
| 设置 | 手机端 `PhoneSettingsActivity`（列表 → 内容）与车机端 `launcher/SettingsActivity`（双栏）共用 `launcher/settings` 下的 Fragment；车机竖屏窄屏时转发到手机端样式 |
| 车机桌面 | `launcher/`：`VirtualLauncher`（1636 行）、`GridActivity`（833 行）、`DockActivity`（317 行）、`LetterboxHint*`（800+ 行）；运行在投屏用的虚拟显示上 |
| 对话框 | `DarkMessageDialog`、`ReceiverDetectionDialog`（397 行）、`BtIdentityDialog`、`WhatsNewDialog`、`PanelWindow`，各自带样式 |
| 已有资产 | `m3_*` 色调令牌（`colors.xml`）、`SignalWavesView`、英雄卡状态机（`HeroState`）、分层进度条（`ConnectionProgress`，纯逻辑，可直接复用） |

主要痛点：

1. 主界面一次性展示约 30 项，用户在「还没连上」的核心路径上被设置项干扰；
2. 排障入口分散（导出报告在英雄卡、日志在底部、抓包在更下面）；
3. 同一信息在多处重复表达（状态摘要、进度条、日志、准备清单）；
4. 样式靠复制粘贴，改一处要改很多处；
5. 一个 Activity 承载太多职责，任何改动都有回归风险。

## 3. 设计原则

1. **连接路径优先**：未连接时只突出「当前状态 + 唯一主操作」；已连接时突出「画面/声音/触控是否在工作」。
2. **渐进披露**：准备项全部就绪后折叠成一行；高级项和日志放到二级页面。
3. **一处表达一件事**：英雄卡给结论，进度条给层级，详情页给证据，日志给原始记录。
4. **证据分层**：保持现有措辞规则——「收到源数据」「已发送」「接收端显示/有声」是不同层级，界面不得合并成「成功」。
5. **令牌是唯一颜色来源**：新视觉为「清透」（方向 B，见 5.1），浅色为主、配套暗色；布局里不再写十六进制颜色。
6. **车机端可读优先**：车机桌面按「远距离、触控、无键盘」设计，与手机端共用令牌但不共用密度。

## 4. 信息架构

### 4.1 手机端

底部三个入口，替代「一页长列表」：

```
连接（默认）        设置                诊断
├ 状态英雄卡        ├ 车机显示          ├ 导出脱敏诊断报告
├ 分层进度条        │  壁纸/方向/超采样  ├ 最近一次连接时间线
├ 下一步提示        ├ 桌面与 Dock        ├ 运行日志（控制台）
├ 准备清单（可折叠）├ 默认地图          ├ 蓝牙抓包分析
└ 目标车机/检测     ├ 音频与声音        ├ CarWith 自检 / 外接车机
                    ├ 语言 / 更新       └ 调试桥（remote 版）
                    └ 关于与免责声明
```

要点：

- **连接页**只保留：英雄卡、分层进度条与「当前/停在」提示、准备清单（Shizuku、本机蓝牙地址、蓝牙配对、检测当前车机）。全部就绪后准备清单折叠成「准备就绪 4/4」。
- **诊断页**集中所有排障能力；连接失败时，英雄卡上的「导出脱敏诊断报告」保留一个直达入口。
- **设置页**沿用现有 Fragment 面板（`DesktopPanelFragment`、`DisplayPanelFragment` 等），只换宿主与外观。
- 横屏：连接页左侧固定英雄卡、右侧滚动（保留现有 `applyContentLayout` 的意图）；平板/折叠屏用双栏。

### 4.2 车机桌面（投屏侧）

保留现有能力和入口，不改信息结构，只做：

- 统一 Dock、Grid、设置双栏的令牌（颜色、圆角、字号），触控目标不小于 48dp（车机上按屏幕物理尺寸再核对）；
- 把 `LetterboxHint*` 的提示样式并入通用「浮层提示」组件；
- 设置双栏与手机设置共用同一组件库。

### 4.3 对话框与浮层

统一为三种：**确认框**（`DarkMessageDialog` 升级）、**底部面板**（目标设备选择、检测向导）、**轻提示**（`snack`、`SettingsToastHost`）。各 Dialog 只提供内容，不再各自带背景和按钮样式。

## 5. 设计系统

- **颜色**：见 5.1。旧的 `m3_*` 令牌在迁移期保留别名，阶段 0 完成后逐步删除；进度条各状态使用语义令牌 `status_*`。
- **字号阶梯**（取代 12 种散落字号）：`display 22` / `title 17` / `body 14` / `label 12` / `caption 11`（sp）；等宽日志字体单独一档。
- **间距**：4dp 基准，常用 `4 / 8 / 12 / 16 / 24`。
- **圆角**：`card 20` / `control 14` / `chip 999`。
- **通用组件**：`StatusCard`、`StepperView`（把现在的 SpannableString 进度条换成自定义 View，支持无障碍朗读）、`SectionHeader`、`SettingRow`（图标+标题+副标题+尾部控件）、`TonalButton / PrimaryButton`、`Switch`、`Chip`、`BottomSheet`。
- **无障碍**：所有状态颜色同时有文字或图标；步骤状态不再只靠颜色（现在已有 ✓ ● ✗ ■ 标记，保留）；`contentDescription` 补齐；支持 200% 字体缩放不截断。
- **多语言**：中英文字符串保持一一对应，新增文案同时补 `values-en`。

### 5.1 视觉方向：清透（已选定）

冷白底加靛蓝，大圆角卡片，轻量明亮；信息靠层级和留白表达，不靠大面积色块。

| 令牌 | 浅色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `surface` | `#F3F5FA` | `#10131C` | 页面底 |
| `card` | `#FFFFFF` | `#181C28` | 卡片、面板 |
| `border` | `#DFE3F0` | `#2A3042` | 0.5dp 细线 |
| `track` | `#E3E6F2` | `#2A3042` | 进度条未到达段、分隔 |
| `text` | `#161B2E` | `#E8EBF5` | 正文 |
| `text_secondary` | `#5F6785` | `#9AA2BD` | 说明、元数据 |
| `primary` | `#3B4BDB` | `#8F9AF0` | 主按钮、当前层、选中 |
| `primary_soft` | `#8F9AF0` | `#4B58B8` | 进行中的段、浅色强调底 |
| `on_primary` | `#FFFFFF` | `#10142E` | 主色上的文字 |
| `status_ok` / `warn` / `error` | 待定（绿 / 琥珀 / 红） | 待定 | 成功、需注意、失败；每个同时配浅底 |

说明：

- 以上是示意稿取值，阶段 0 落地时要用工具核对文字与背景的对比度（正文和说明至少 4.5:1），不达标就调深。
- 一个页面最多一个主色实心按钮；其余用描边或浅底按钮。
- 状态不只靠颜色：保留 ✓ ● ✗ ■ 标记和文字。
- 暗色由系统深色模式触发，也可在设置里手动指定；车机桌面沿用暗色版本。

**连接页状态卡**（示意稿的组件化）

- 顶部小标签「连接状态」，下面是状态标题（未连接 / 正在连接 / 已连接 / 连接失败）。
- 7 段分层进度条（蓝牙、入网、发现、配对、会话、CarWith、画面）：已完成段为主色，进行中段为 `primary_soft`，失败段为 `status_error`，未到达段为 `track`。下方一行说明「当前层 耗时 · 当前缺的那一步」。
- 副行显示已用时间。只有在确认是艾瑞泽 8 车机时才显示「车机窗口约 30 秒」；其他车机只显示已用时间，避免把一台车机观察到的窗口当成通用结论。
- 主按钮在卡片下方（启动连接 / 取消连接 / 导出诊断报告）。
- 底部导航：连接、设置、诊断。

## 6. 技术路线

| 方案 | 做法 | 优点 | 代价 / 风险 |
| --- | --- | --- | --- |
| A. 保留 Views，重做结构与视觉（推荐起步） | 拆分 `MainActivity` 为连接/设置/诊断三个 Fragment 加若干 Controller；`values/` 下建令牌与样式；自定义 `StepperView`、`SettingRow` 等 | 不新增依赖、APK 不变大；车机桌面的虚拟显示、`PanelWindow`、`ScreenDimmer` 等 View 代码无需迁移；风险最低 | 视觉改造要手写较多 XML |
| B. 手机端迁移到 Compose，车机桌面保留 Views | 手机端 `ComposeView` 逐屏替换 | 手机端开发效率高、状态驱动、预览方便 | 新增 Compose 依赖与构建时间；`R8` 当前关闭，APK 增量明显；两套 UI 技术并存 |
| C. 全部 Compose | 含车机桌面 | 一致 | 车机桌面运行在虚拟显示与自建窗口上，触控注入、Letterbox 都依赖 View 层，风险高，不建议 |

建议：**先走 A，把「拆分 + 令牌 + 组件」做完**；之后如果仍想用 Compose，再按屏幕单独评估 B。A 完成后，每一屏的外壳已经是独立组件，迁移成本会很低。

## 7. 约束与验证

- `MainActivity` 重构不得改变连接流程：权限、蓝牙/Wi-Fi 引导、`startConnectionNow` 链路的顺序和分支保持原样，先抽取、后改样式。
- 车机桌面改动会影响真车观感与触控，合并前需要按项目要求在 DiPlay、WinPlay、macplay、奇瑞艾瑞泽 8 上回归；没有记录的真车证据，不在文档里写「已支持」。
- 每个 PR 跑完整检查：`spotlessCheck`、标准版单元测试、`lintStandardDebug`、`assembleStandardDebug`、remote 桥接测试；纯逻辑（状态到界面模型的映射）补单元测试。
- 手机端改动在模拟器上截图验证（空闲、等待、失败、已连接、横屏、200% 字体、英文）；PR 附截图。
- README 中若有对界面的描述同步更新，`README.md` 与 `README.zh-CN.md` 保持等价；`docs/screenshots/` 里的是真车证据图，不随界面改版替换。
- 新增诊断字段继续走 `DiagnosticRedactor`；本次不计划新增字段。
